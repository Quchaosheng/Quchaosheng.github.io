核心文章

CORE GUIDES

这十篇不是按发布时间挑的，而是按“解决工程问题时最常反复回来的基础问题”挑的。先从这里进入，再按[学习路径](/paths/)扩展到完整专题。

01 · REAL-TIME LINUX

PREEMPT_RT：Linux 怎样变成可抢占的实时内核

理解 RT 内核改变了什么、还保留哪些不可抢占路径，以及为什么它不是硬实时保证。

02 · REAL-TIME LINUX

CPU 隔离：为实时任务留出安静的核心

把 CPU、IRQ、RCU、workqueue 和后台负载的归属设计成可验证的资源布局。

03 · MEASUREMENT

cyclictest：怎样测量 Linux 实时调度延迟

从周期、亲和性和尾延迟出发，建立可以复测的系统唤醒基线。

04 · DIAGNOSIS

osnoise tracer：把实时抖动拆成可解释的噪声

将延迟尖峰关联到 IRQ、softirq、调度、NMI/SMI 或其他系统干扰。

05 · ROBOT PLATFORM

Jetson 机器人部署：功耗、算力与实时控制怎样分工

把 GPU 推理、ROS 2 运行时与 MCU/RT 控制放到合适的责任边界上。

06 · ROBOT DATA PIPELINE

Isaac ROS NITROS：相机数据怎样少拷贝地送进 GPU

理解少拷贝带来的吞吐优势，以及缓冲区生命周期、数据年龄和同步的代价。

07 · ROBOT INFERENCE

TensorRT 机器人推理：从训练模型到稳定延迟

不只看 engine 吞吐，而是把预处理、队列、推理、后处理和控制消费串成端到端指标。

08 · BUILD CONTRACT

CMake 交叉编译：工具链文件决定目标环境

防止构建过程误用宿主机依赖，把 sysroot、编译器和查找规则固化为工程契约。

09 · SYSTEM DELIVERY

Buildroot：生成可复现的嵌入式 Linux 系统镜像

从 defconfig、外部树和 package 组织可重建的交付物，而不是一次性的本机镜像。

10 · DEVICE PROTOCOL

CAN 总线：仲裁、错误处理与可靠通信

在协议、错误状态、bus-off 和恢复策略层面理解真实设备通信的约束。

这些文章的共同原则是：先拆分系统边界，再用数据验证；所有看似“快一点”或“跑通了”的描述，都要说明环境与适用范围。
