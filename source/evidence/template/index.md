<div class="page-lead"><p class="section-kicker">REPRODUCIBLE RECORD</p><p>每一次测量、仿真或台架验证都从同一份记录结构开始。模板不会把一次成功写成普遍结论，它要求把可复查工件和不能外推的部分一起留下。</p></div>

<div class="note-flow"><span>定义问题与阈值</span><i>→</i><span>冻结环境与输入</span><i>→</i><span>运行并保存工件</span><i>→</i><span>解释结果与边界</span><i>→</i><span>决定补测 / 回归 / 回滚</span></div>

## 使用规则

1. 先写通过阈值和失败动作，再运行命令。
2. 不覆盖失败工件；新尝试用新的运行 ID 和目录。
3. 记录原始输出的位置与哈希，而不是只贴一张成功截图。
4. 结论要写明“本次能证明什么”和“不能证明什么”。

## 记录骨架

```markdown
---
title: "<实验名称>"
date: "<YYYY-MM-DD>"
project: "<仓库或项目>"
run_id: "<唯一运行 ID>"
evidence_class: "implementation | simulation | vcan | physical_io | formal_test"
status: "passed | failed | interrupted | blocked"
---

# 1. 问题与验收阈值

- 要回答的问题：
- 通过条件：
- 失败条件与安全动作：
- 本次不试图证明的内容：

# 2. 环境快照

- 硬件 / 台架：
- OS / 内核 / 固件：
- 依赖与工具版本：
- Git commit 与工作区状态：
- 启动参数、CPU / IRQ / 电源策略：

# 3. 输入与执行

- 工作负载、持续时间、并发和 seed：
- 完整命令：
- 输入数据或模拟故障：
- 输出目录：

# 4. 原始工件

| 工件 | 路径或链接 | SHA-256 | 说明 |
| --- | --- | --- | --- |
| 环境报告 | | | |
| 日志 / trace | | | |
| 统计结果 | | | |
| 失败现场 | | | |

# 5. 结果

- 观察到的数值或状态：
- 与阈值的比较：
- 失败时的最早异常证据：

# 6. 结论范围

- 本次支持的结论：
- 不支持或不能外推的结论：
- 已知混杂因素与剩余风险：

# 7. 后续动作

- [ ] 补测
- [ ] 回归测试
- [ ] 修复
- [ ] 回滚
- [ ] 明确暂不验证及原因
```

项目页和[证据日志](/evidence/)应只引用已经有对应记录和工件的结论。真正的实验结果出现后，再把这份骨架替换为该次运行的事实。
